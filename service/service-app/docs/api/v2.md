# Attribution Service API: V2

| | |
|---|---|
| **Status** | V2 is the going-forward API; `/latest` aliases V2 |
| **V1 status** | Still served at `/v1`. Kept for backward compatibility with existing consumers (consumers that pin `/v1` explicitly). No deprecation date yet. |
| **OpenAPI** | `GET /docs` (Swagger UI). Schemas tagged with `V1` / `V2` suffixes. |

V2 is a wire-shape redesign. The request payload is more explicit (callers specify node to ranks mapping exactly), the response is flatter (one top-level verdict plus a symptom-major map), and rule-specific knobs are now generic instead of hardcoded into the schema.

This page is the V1-vs-V2 reference. If you are wiring up a new client, build against V2. If you are on V1, the migration is mostly mechanical and laid out in [Migration sketch](#migration-sketch-v1-to-v2).

## At a glance

| Concern | V1 | V2 |
|---|---|---|
| Route prefix | `/v1` | `/v2` (and `/latest`) |
| Workload `nodes` shape | `list[str]` plus `nranks`, `ranks_per_node` (rank mapping inferred) | `dict[str, list[int]]` (explicit per-node ranks) |
| Workload `type` | `WorkloadTypeEnum` (closed set) | `str` (open) |
| Attribution parameters | Typed per rule (`nvrx_straggler_parameters`, `megatron_straggler_parameters`) | Generic `rule_params: dict[RuleId, RuleParameters]`, validated against each rule's declared params model at request time (only collector rules supported) |
| Response top level | `attributions: list[<discriminated union>]` (NodeAttribution, GlobalAttribution, StorageAttribution, SwitchAttribution, WorkloadRecord) | `verdict: Verdict` + `symptoms: dict[Symptom, list[SymptomSite]]` + `collectors: dict[str, Any]` |
| Straggler details | Hand-packed into `StragglerAttribution` items per node | Raw collector digest under `collectors["nvrx_straggler"]` / `collectors["megatron_straggler"]`, JSON-encoded |
| `JobInfo` validation failures | HTTP 500 | HTTP 422 with structured `errors` |
| Rule-param validation failures | n/a (params were typed) | HTTP 422 (`RuleAcceptsNoParamsError`, `InvalidRuleParams`) |
| Rule ID vs digest name | Same shape (typed fields) | Distinct keyspaces: `rule_params` keys are rule IDs (e.g. `Collect.NVRXStraggler`), `collectors` keys are per-rule digest names (e.g. `nvrx_straggler`) |

## Request changes

### Workload: explicit node-to-rank mapping

V1 took a flat node list plus rank counts and relied on the library to synthesize the per-node rank assignment:

```jsonc
// V1 POST /v1/attributor
{
  "workload": {
    "id": "test-001",
    "type": "slurm",
    "job_start_time": "2026-03-30T00:00:00Z",
    "job_end_time":   "2026-03-30T01:00:00Z",
    "status": "FAILED",
    "nranks": 16,
    "ranks_per_node": 8,
    "nodes": ["node-01", "node-02"],
    "name": "test", "username": "tester", "framework": "pytorch"
  },
  "metadata": { "cluster": "cluster-a", "agent": "test", "tenant": "test", "ruleset": "default" }
}
```

V2 requires the caller to declare the mapping directly. No more inference, no more ragged-rank surprises:

```jsonc
// V2 POST /v2/attributor
{
  "workload": {
    "id": "test-001",
    "type": "slurm",
    "job_start_time": "2026-03-30T00:00:00Z",
    "timezone": "UTC",
    "job_end_time":   "2026-03-30T01:00:00Z",
    "status": "FAILED",
    "nodes": {
      "node-01": [0, 1, 2, 3, 4, 5, 6, 7],
      "node-02": [8, 9, 10, 11, 12, 13, 14, 15]
    },
    "name": "test", "username": "tester", "framework": "pytorch"
  },
  "metadata": { "cluster": "cluster-a", "agent": "test", "tenant": "test", "ruleset": "default" }
}
```

Why: clients have more knowledge on the execution context itself, and may already know the exact mapping. V1 inferred it by heuristic and would fail opaquely on edge cases (non-uniform `ranks_per_node`, sparse rank IDs, etc.). V2 fails at request validation with a 422 instead.

### Workload `type` relaxed to `str`

V1 enforced `WorkloadTypeEnum` (closed set). V2 accepts any string. This unblocks callers from other workload managers without a server-side enum bump. Validation that the workload type is something rules can consume happens later, in the library.

### Attribution parameters: rule-keyed generic dict

V1 had typed parameter classes for each known straggler family:

```jsonc
// V1
"parameters": {
  "nvrx_straggler_parameters":     { "straggler_threshold": 0.7,  "score_types": ["RELATIVE"] },
  "megatron_straggler_parameters": { "straggler_threshold": 0.95, "score_types": ["INDIVIDUAL"], "infer_threshold_from_data": true }
}
```

V2 makes this generic. Each rule declares a `params_model`; the service validates the dict against the model at request time. Unknown rule IDs and shape mismatches both return 422.

```jsonc
// V2
"parameters": {
  "rule_params": {
    "Collect.NVRXStraggler":     { "params": { "straggler_threshold": 0.7,  "score_types": [0] } },
    "Collect.MegatronStraggler": { "params": { "straggler_threshold": 0.95, "score_types": [1], "infer_threshold_from_data": true } }
  }
}
```

Notes on this example:

- Keys are **rule IDs** (`Collect.NVRXStraggler`, `Collect.MegatronStraggler`), not the snake-case digest names that show up in the response's `collectors` field. The two keyspaces are intentionally distinct: rule ID is the lib's registration name, digest name is what the rule chooses to call its output.

Why: adding a new rule with parameters no longer requires a service-side schema change. The library owns the param shape.

Two new error responses to be aware of:

| Status | Error | When |
|---|---|---|
| 422 | `RuleAcceptsNoParamsError` | Caller sent params for a rule that does not take any |
| 422 | `InvalidRuleParams` | Caller sent params that fail the rule's `params_model` validation |

## Response changes

### Top-level shape

V1 returned a discriminated union of attribution objects. The client had to walk the list and switch on `type`:

Example V1 response from a SLURM-failed job with no observations ingested:

```json
{
  "attributions": [
    {
      "type": "GlobalAttribution",
      "attributions": [
        {
          "type": "SingleAttribution",
          "symptom": "job failed",
          "description": "Not Applicable",
          "attribution_class": "user",
          "recommendation": "unknown",
          "sources": [ ... ]
        }
      ]
    }
  ],
  "observation_context": [],
  "model_type": "AttributionResponseV1"
}
```

Two levels: an outer container (`GlobalAttribution`, `NodeAttribution`, etc.) and an inner per-symptom attribution (`SingleAttribution`, `StragglerAttribution`).

V2 splits this into three orthogonal fields: a single top-level verdict, a symptom-major map, and a raw collectors digest:

Example V2 response from the same SLURM-failed job with no observations ingested. The lib falls back to a `"job failed"` symptom sourced from the SLURM status itself; with real observations ingested, `symptoms` and the straggler collectors fill in:

```json
{
  "verdict": {
    "attribution_outcome": "Fail User",
    "detail": "Not Applicable",
    "root_symptom": {
      "symptom": "job failed",
      "source": { ... }
    }
  },
  "symptoms": {
    "job failed": [
      { "type": "ResourcelessSource", "source": { ... } }
    ]
  },
  "observation_context": [],
  "collectors": {
    "nvrx_straggler": {...},
    "megatron_straggler": {...},
  },
  "model_type": "AttributionResponseV2"
}
```

What this gets you:

| Field | What it is |
|---|---|
| `verdict` | Single top-level answer. `attribution_outcome` is the raw library compatibility label; `detail` is free-form (for example, `"GPU XID 79"`); `root_symptom` is the driving symptom and source, or `null`. |
| `symptoms` | Symptom-major index. Each value is a list of `SymptomSite`: `NodeSource` (`node` + `source`) or `ResourcelessSource` (`source` only). |
| `collectors` | Lib's raw digest, `dict[str, Any]`. Schema evolves with the lib, not the service. Keys (snake_case digest names) are distinct from `rule_params` rule IDs. |
| `model_type` | Literal discriminator: `"AttributionResponseV2"` (V1 returns `"AttributionResponseV1"`). |

### Optional runtime Decision DAG

Add `include_decision_graph=true` to `GET /v2/attributor/{att_id}/attribution` to include the runtime
Decision DAG under `verdict.decision_graph`. The graph contains typed evidence, rule-action, and
outcome nodes plus their directed edges. When the option is omitted or false, the service does not
record the graph and omits `decision_graph` from the verdict.

### Error responses

V1 mapped library `JobInfoError` to HTTP 500. V2 maps these to HTTP 422 with the same `errors`/`body`/`message` shape used by request-validation failures. Combined with the rule-param 422s above, every client-fixable failure is now a 4xx.

Once a request passes model validation, observation ingestion can still fail on the body itself: a malformed structured body or an incompatible source/format pair returns a discriminated HTTP 400 response. (An unrecognized `format` value is rejected earlier by request validation with HTTP 422, not 400.) The interactive OpenAPI docs provide named examples for each of the three 400 response variants. Structured bodies for `loki_dict_list`, `raw_loki_streams`, `ufmlog`, `prometheus_metrics`, and `csp_event_list` are decoded before entering the attribution library. The V1 and V2 observation endpoints share this behavior.

## Migration sketch (V1 to V2)

1. **Client computes rank mapping.** Fold `nranks` / `ranks_per_node` / `nodes` into `nodes: dict[str, list[int]]`, e.g. `{"node-01": [0,1,2,3], "node-02": [4,5,6,7]}`.
2. **Rewrite parameters** under `rule_params`, keyed by rule ID, wrapped in `{ "params": {...} }`. `score_types` is now an `IntEnum` (`0`=RELATIVE, `1`=INDIVIDUAL).
3. **Reshape response handling.** Drop the discriminated-union walk. Read `verdict` for the top-level answer, `symptoms` for the per-symptom site list, and `collectors["nvrx_straggler"]` / `collectors["megatron_straggler"]` for rank-level straggler detail.
4. **Switch URLs.** `/v1/...` → `/v2/...`, or use `/latest/...` (currently aliases V2).
5. **Expect 422s.** If your client treats 4xx as fatal, the new validation paths (bad rank mapping, bad rule params) will start surfacing there.
